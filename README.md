## 1. 项目概述

#### 		1.1 课题背景

##### 				【题目1】通信网络设计问题：

​	将某国的国土简化为欧几里得二维平面，某国有N个城市。我们将一个城市看作一个顶点。两个顶点之间的边是两个城市之间的通信线路。我们考虑简单图。也就是说，每两个顶点之间最多只有一条边。

​			最短路径（Dijkstra算法）

​			最小生成树（Kruskal算法）

​			旅行商问题（贪心+2-opt优化）

​			施泰纳树（MST+费马点优化）

​		**可视化：** 地图交互显示，算法执行动画，实时日志输出

​		**测试规模：** 支持220个城市，293条线路的大规模网络

## 2. 数据格式

#### 		2.1 城市数据（cities.json）

​	系统采用轻量级的 **JSON文件** 存储城市的各项基本信息以及通信线路数据。数据格式采用对象数组形式，便于后续的扩展和前后端数据的交互。

​	**城市文件数据格式**：文件包含一个由多个对象组成的数组。每个对象代表一个城市，记录了城市的唯一标识符 id、城市名称 name、横坐标 x、纵坐标 y 以及简介 description。两座城市之间的距离通过其坐标的欧几里得距离计算并四舍五入取整得到。

```json
  {
    "id": "1",
    "name": "北京",
    "x": 11640,
    "y": 3990,
    "description": "首都（直辖市）"
  },
  {
    "id": "2",
    "name": "上海",
    "x": 12147,
    "y": 3123,
    "description": "直辖市"
  }
```

​		**设计考虑：**

​		1、ID采用字符串类型，便于扩展

​		2、坐标使用整数，避免浮点精度问题

​		3、description字段可选，用于标注城市类型

#### 		2.2 线路数据（routes.json）

​		线路数据记录城市间的连接关系。

```json
{
  "id": "1",
  "source": "1",
  "target": "2",
  "type": "trunk"
}
```

​		**重要特性：**

​		1、线路是无向的，(A,B)和(B,A)表示同一条线路

​		2、线路长度不存储，根据城市坐标实时计算

​		3、计算公式：`length = sqrt((x2-x1)² + (y2-y1)²)`

​		4、这样设计的好处是城市坐标更新时，线路长度自动更新，保持数据一致性



## 3. 数据结构设计

#### 		3.1 核心结构

​		**City结构体：** 封装城市的ID、名称、坐标、描述信息

​		**Edge结构体：** 表示线路，包含起点、终点、长度

​		**Graph类：** 图的核心数据结构，管理所有城市和线路

```cpp
// 1. 城市节点结构体
struct City {
    int id;                    // 城市唯一标识符
    std::string name;          // 城市名称
    int x;                     // X 坐标
    int y;                     // Y 坐标
    std::string description;   // 城市简介
    City() : id(0), x(0), y(0) {}
    City(int id, const std::string& name, int x, int y, const std::string& desc = "")
        : id(id), name(name), x(x), y(y), description(desc) {}
};

// 2. 边（线路）结构体
struct Edge {
    int from;      // 起点城市 ID
    int to;        // 终点城市 ID
    int length;    // 线路长度（根据两城市坐标计算的欧几里得距离）
    Edge() : from(0), to(0), length(0) {}
    Edge(int f, int t, int len) : from(f), to(t), length(len) {}
};

// 3. 图的核心存储结构
class Graph {
private:
    std::vector<City> cities;                              // 存储所有城市对象
    std::map<int, int> cityIdToIndex;                      // 城市ID到数组索引的映射（解决ID不连续问题）
    std::vector<std::vector<std::pair<int, int>>> adjList; // 邻接表：pair<邻居索引, 距离>
    std::vector<std::vector<int>> adjMatrix;               // 邻接矩阵：-1表示无直接线路
    // ... 方法略
};
```



#### 	3.2 图的存储结构

​		本系统采用**邻接表+邻接矩阵双重存储**。

​		不同算法对数据结构有不同需求：

​		**DFS/BFS遍历**：需要快速访问邻居 → 邻接表O(degree)

​		**查询特定边**：需要快速判断两点是否相连 → 邻接矩阵O(1)

​		**空间换时间**：虽然占用更多内存，但大幅提升算法效率



​		**三个核心数据结构：**

```cpp
class Graph {
private:
    std::vector<City> cities;                              // 存储所有城市
    std::map<int, int> cityIdToIndex;                      // 城市ID到数组索引的映射
    std::vector<std::vector<std::pair<int, int>>> adjList; // 邻接表：每个城市的邻居列表
    std::vector<std::vector<int>> adjMatrix;               // 邻接矩阵：存储城市间距离
}
```

​		**邻接表（adjList）**

​			存储每个城市的邻居列表

​			每个元素是pair<邻居索引, 距离>

​			适合稀疏图，空间O(V+E)

​		**邻接矩阵（adjMatrix）**

​			二维数组，matrix[i][j]存储距离

​			-1表示无直接连接

​			空间O(V²)，查询O(1)

​		**ID映射表（cityIdToIndex）**

​			解决ID不连续问题

​			城市ID可能是1,5,100，但数组索引必须0,1,2连续

​			使用map建立映射关系

## 5. 打印所有城市和通信线路的地图

#### 		5.1 连通性判断算法

​		**DFS深度优先搜索：**

​			算法从任意节点出发，递归访问所有能到达的节点。如果能访问到所有节点，说明图连通。

​		**核心思想：**

​			1、标记当前节点为已访问

​			2、递归访问所有未访问的邻居

​			3、最后检查是否所有节点都被访问

​		**时间复杂度：** O(V+E)，V是城市数，E是线路数

​		**找出连通分量：**

​			遍历所有节点，每次遇到未访问节点就启动一次DFS，找出一个连通分量。使用栈代替递归，避免栈溢出。

​			例如：如果图有3个孤立部分，会返回3个连通分量列表。

#### 	5.2 使图连通的最小代价方案

​			当图不连通时，系统自动计算需要添加哪些线路才能使图连通，并保证总长度最小。

​		**算法步骤：**

​		**1、找出所有连通分量**

​			使用DFS找出图中的所有连通部分

​			例如：分量1有156个城市，分量2有35个城市，分量3有12个城市

​		**2、计算分量间最短边**

​			对每两个连通分量，暴力枚举所有城市对

​			找出距离最短的连接边

​			例如：分量1和分量2之间，西宁到拉萨距离最短(1247km)

​		**3、Kruskal算法选择最短边**

​			将所有分量间的边按距离排序

​			使用并查集贪心选择最短边

​			确保不形成环

​			n个连通分量需要n-1条边连接

​		**并查集的作用：**

​			快速判断两个分量是否已经连通

​			路径压缩优化：find操作时将节点直接连到根节点

​			按秩合并：将较小的树合并到较大的树

​		**时间复杂度：** O(V+E+k²×n²)，k为分量数，n为平均分量大小

## 6. 查询城市信息

#### 		6.1 最短路径算法（Dijkstra）

​			Dijkstra算法是经典的单源最短路径算法，适用于边权非负的图。

​		**算法核心思想：**

​			**1、维护距离数组**：记录起点到每个节点的当前最短距离

​			**2、优先队列优化**：每次取出距离最小的未访问节点

​			**3、松弛操作**：如果通过当前节点到邻居的距离更短，就更新邻居的距离

​		**路径回溯**：通过parent数组记录路径，从终点回溯到起点

​		**算法步骤：**

​			1、初始化：起点距离为0，其他节点为无穷大

​			2、将起点加入优先队列

​			3、循环：取出距离最小的节点u

​			4、对u的所有邻居v进行松弛：如果dist[u]+weight(u,v) < dist[v]，更新dist[v]

​			5、将更新后的v加入优先队列

​			6、重复直到队列为空

#### 		6.2 按距离排序显示

​			算法计算完成后，将所有结果按距离从小到大排序，方便用户查看最近的城市。

## 7. 遍历全部城市（变形的旅行商问题）

#### 		7.1 问题描述

​	旅行商问题(TSP)是经典的NP-hard问题：给定一组城市，找一条路径访问所有城市恰好一次，使总路径长度最短。

​		**本系统采用的方案：** 贪心算法构造初始解 + 2-opt局部优化

#### 		7.2 算法设计

​		**第一阶段：贪心构造初始解**

​	从起点开始，每次选择距离当前位置最近的未访问城市。这是最简单的启发式算法，虽然不保证最优，但能快速得到一个还不错的解。

​		**算法流程：**

​			1、从起点开始，标记为已访问

​			2、在所有未访问城市中，找距离当前位置最近的

​			3、移动到该城市，标记为已访问

​			4、重复步骤2-3，直到访问完所有城市

​			5、如果是闭合式TSP，最后返回起点

​		**时间复杂度：** O(n²)

​		**第二阶段：2-opt局部优化**

​			2-opt是经典的TSP优化算法，通过交换边来改进路径。

​		**核心思想：**

​			选择路径中的两条边(a->b)和(c->d)

​			尝试删除这两条边，改成(a->c)和(b->d)

​			这相当于反转中间的路径段

​			如果新路径更短，就接受这个改变

​			重复直到无法改进

​		**举例说明：**
```
原路径: A -> B -> C -> D -> E -> F
选择边: (A->B) 和 (D->E)
反转后: A -> D -> C -> B -> E -> F
        (中间段B->C->D被反转为D->C->B)
```

#### 		7.3 距离缓存优化

​			TSP算法会频繁查询两城市间的最短距离。如果每次都重新计算，会非常慢。

​		**解决方案：**

​			 使用map缓存已计算的距离

​			第一次查询(A,B)时，用Dijkstra计算并缓存

​			后续查询直接返回缓存结果

​			大幅减少重复计算

## 8. 施泰纳最小树问题

#### 		8.1 问题描述

​	施泰纳树问题：给定N个城市坐标，从空白开始设计最短通信线路使N个城市连通。与最小生成树不同，施泰纳树允许添加辅助顶点（Steiner点）来减少总长度。

​		**实际意义：** 在通信网络设计中，可以在关键城市之间设置中继站，从而减少总线路长度，降低建设成本。

#### 		8.2 算法设计

​		**核心思想：** MST初始化 + 费马点优化

​	施泰纳树是NP-hard问题，本系统采用启发式算法：先用Kruskal算法计算最小生成树作为初始解，然后迭代优化，尝试用Steiner点替换度数≥3的节点。

​		**费马点（Fermat Point）：**

​	费马点是到三角形三个顶点距离之和最小的点。对于三个城市A、B、C，如果用费马点F连接它们，总距离FA+FB+FC最小。

​		**两种情况：**

​		**1、钝角三角形**：如果三角形有角≥120°，费马点就是那个钝角顶点

​		**2、锐角三角形**：费马点在三角形内部，到三个顶点的连线夹角都是120°

​		**Weiszfeld迭代算法：**

​			这是计算费马点的数值方法，基于加权几何中位数：

​			1、初始点取三角形重心

​			2、迭代公式：新位置 = 三个顶点的加权平均，权重 = 1/距离

​			3、距离越近的顶点权重越大

​			4、迭代直到收敛（变化<1e-7）或达到最大次数（100次）

​		**主算法流程：**

​		**1、初始化**：用Kruskal算法计算MST

​		**2、迭代优化**（最多50次）：

​			找出度数≥3的节点（分支点）

​			对每个分支点，尝试其所有三元组邻居

​			计算三个邻居的费马点

​			如果费马点能减少总长度，用它替换原节点

​			检查连通性，确保所有关键城市仍然连通



#### 		8.3 算法优化

​		**连通性检查：** 每次修改后必须检查所有关键城市是否仍然连通，使用BFS验证。

​		**Steiner点标记：** 使用负整数ID（-1, -2, -3...）区分Steiner点和真实城市。

​		**迭代终止条件：**

​			达到最大迭代次数（50次）

​			连续迭代无改进

## 10.设计总结

​	**项目回顾与分析：**
​		本次通信网络设计系统采用了 C++11 开发底层核心算法，辅以 React18 和 PixiJS 搭建了高现代化的前端界面，通过自定义的极简 HTTP 服务器实现了前后端通信。这种架构使得繁重的图论算法（如 Dijkstra、TSP 和 Steiner 树）能在 C++ 端高速运行，同时保证了前端绘制大于 200 个节点时的流畅性（基于 WebGL 的图形硬件加速）。

​	**调试过程中的问题与解决经验：**

​	**1、节点索引问题：** 在初始设计时，城市 ID 是与数组下标强绑定的。当实现“删除城市”功能时，直接删除导致后续节点数组下标集体偏移，引发了数组越界崩溃。最终通过引入 std::map 机制，在每次删除城市后重建映射，成功解耦了业务 ID 和底层数组索引。

​	**2、TSP性能瓶颈：** 在 200 个节点测试 TSP 时，由于图并非任意两点都有直接边连接，频繁的路线回溯引发大量重复最短路径计算，导致系统卡死。我最终引入了 DistanceCache 缓存机制，命中缓存直接返回 O(1)，未命中才跑 Dijkstra，计算速度实现了数量级跃升。

​	**3、施泰纳树的数值稳定性：** 计算费马点最初尝试了几何旋转法，但在特殊锐角或钝角边界处易发生浮点数精度灾难。后改用迭代求加权几何中位数的 Weiszfeld 算法，限制了最大 100 次迭代，极大地增强了算法处理任意散点数据的鲁棒性。

##### 	总结:

​		本次课程设计是一次完整的软件开发实践，从需求分析、系统设计、编码实现到测试调试，每个环节都有深刻体会。最大的收获是理解了"没有完美的算法，只有合适的算法"。对于NP-hard问题，实用的近似算法往往比追求最优解更有价值。
